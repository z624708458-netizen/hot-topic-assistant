# 热点雷达 V2 · 每日科技/商业短视频选题助手

在 V1 的 GitHub Pages 页面与 UI 上升级，免费公开 RSS + GitHub Actions 定时采集 + 静态 JSON。不需要新增账号、服务器或付费 API Key，不调用 AI。

网站：https://z624708458-netizen.github.io/hot-topic-assistant/

## 最简单的免费架构

```text
公开 RSS → GitHub Actions（计划每两小时）
         → data/news.json（真实新闻，保留七天）
         → data/top5.json（近48小时的每日推荐快照）
         → GitHub Pages（原来的 main / 根目录部署）
         → 浏览器用同一套透明规则评分、筛选和生成框架
```

静态浏览器无法可靠跨域读取各媒体 RSS；浏览器端不使用公共 CORS 代理、不绕过网站限制。GitHub Actions 在服务器端读取公开订阅，网页只读取自己站点的 JSON。当前仓库是公开仓库，GitHub 的标准公开仓库 Actions runner 与 Pages 无需付费。工作流只使用 GitHub 自动提供的 `GITHUB_TOKEN`，不要求你购买或提供 API Key。

## 日常使用

- 默认近 48 小时，按总分挑出 Top 5；不足五条不会补编。
- 今天按北京时间自然日；48 小时与 7 天是滚动窗口。所有新闻明确显示原始发布时间到分钟（北京时间），不拿抓取时间代替。
- 公司筛选：小米、华为、腾讯、字节跳动、阿里巴巴、百度、OpenAI、苹果、特斯拉。多公司新闻可以被每个匹配公司的筛选找到。
- 可以筛选 ≥80 分、搜索、查看全部新闻、按发布时间排列。Top 5 模式始终先挑最高分的五条，再应用显示排序。
- 每条有五维分数与关键词依据、推荐理由、普通人视角、3 个标题方向、60–90 秒分段口播框架、原文链接和来源摘要。
- 一键打开原文；标题与框架可复制。收藏保存本机快照，旧收藏不变成新热点。
- 手动新闻仍可录入，但默认不混入公开 RSS 推荐；勾选“包含手动录入”后才显示，始终标记未核验。

## 来源与真实性

来源配置：`config/sources.json`。

当前启用 IT之家、爱范儿、Apple Newsroom、OpenAI 官方新闻的公开 RSS。36氪 `/feed` 实测返回 HTML，已停用并保存原因，不将错误页面当新闻。仅使用这些机器订阅地址，不抓取新闻正文、不绕过 403、登录、验证码或访问禁止。

每条保存标题、带时区的原始发布时间、公司及多公司匹配、媒体、原文 URL、简短摘要、来源 ID、采集时间。摘要直接来自 RSS，最多节选 360 字并标注；缺失摘要不编写。没有明确发布时间/时区、未来新闻、无效或来源域外的链接会跳过。促销领券信息和多事件早报排除，避免词语拼接抬高分数。标题中的“消息称”“曝光”“有望”等标记为待核验，不改写成官方确认。

公司识别是标题关键词和产品别名匹配，官方源有固定公司标签；不是语义理解。源提供的新闻和摘要也不能代替独立核验。传闻、官方计划及媒体分析需保留原文条件。发布短视频前必须打开原文核对。英文原题保留英文，未自动翻译。

覆盖范围有限：首次运行只能读取 RSS 当前提供的条目，七天记录从启用后逐步积累，不保证当天每家公司都有新闻，也不保证全网热点覆盖。不为了补足某家公司或五条推荐制造内容。

## 五维规则评分（100分）

规则在 `assets/rules.js`；浏览器和自动推荐快照共用。五项各 20 分，直接相加。

| 维度 | 规则 |
| --- | --- |
| 大众认知度 | 命中九家重点公司或产品别名20分，其他手动公司8分 |
| 争议性 | 基础4分；价格/隐私/监管/就业/争议五组，每组+4，上限20 |
| 反常识/意外 | 基础4分；首次/意外变化/突破/开放或停止四组，每组+4，上限20 |
| 普通人利益 | 基础4分；价格消费/常用设备/工作学习/用户权益四组，每组+4，上限20 |
| 时效性 | ≤12h 20，≤24h 18，≤48h 14，≤7天6，更早或未来0 |

一组反复出现只计一次。命中关键词不代表存在争议或影响：例如报道“没有涨价”也可能命中“涨价”。分数不是热搜、阅读量、事实可信度或 AI 理解。高分筛选可能为空，不调整分数强行凑数。

推荐理由与角度是固定规则，标题是基于原题的模板；口播是按秒分段的**待填框架**，不生成未经验证的事实成稿。事实段需要阅读原文后填写，完成后朗读调整到 60–90 秒。

## 自动更新与现有 Pages

工作流：`.github/workflows/news-update.yml`。

- 默认分支 main 推送代码时、手动运行时、UTC 每两小时的第17分钟启动（北京时间偶数小时17分）。GitHub 调度可能延迟，没有精确到时的保证。
- 先跑采集与评分测试，再采集并生成 Top 5，将两个 JSON 提交回 main，不推送其他文件。
- 保留七天的有效缓存；单源失败不清空其他新闻，全部失败时保留尚未过期数据、保存失败状态并把工作流标为失败。页面显示每个源的状态与最后成功时间；超过六小时未成功采集时提示延迟。
- 浏览器每五分钟刷新同站 JSON，不在浏览器触发外部采集。网页“刷新数据”只读取已发布快照。
- `GITHUB_TOKEN` 的机器人提交不会自动触发普通 Pages 构建，所以工作流会**显式请求 Pages rebuild**，沿用现有 main / 根目录设置。若 Pages 本来就是 Actions 模式，则使用官方 artifact/deploy 动作。不擅自更改仓库设置或部署来源。
- 如果仓库禁用了 Actions、禁止写权限、Pages 环境要求审核，或者部署来源不是 main / 根目录，工作流会给出错误；需要仓库所有者在 Settings 调整相应现有配置。无需新增第三方账号。
- GitHub 可能按自身策略暂停长期不活跃仓库的定时任务，可在 Actions 中手动重新运行。

查看更新结果：GitHub 仓库 → **Actions** → **Update tech news and Pages**。需要手动刷新新闻时选 **Run workflow**；正常使用无需懂代码。

## 本地开发与测试

Python 3.12+、Node 22+（只用标准库，不需 npm install）。启动：

```sh
python3 -m http.server 8000 --bind 0.0.0.0
```

在本机浏览器访问 `http://localhost:8000`。云机器需要平台的端口转发。本版通过 HTTP 读取 JSON，不建议双击本地 HTML；直接访问已部署网站即可。

采集真实数据并生成快照：

```sh
python3 scripts/collect_news.py
node scripts/rank_news.js
```

验证（浏览器测试额外需 Python Playwright 与 Chromium；当前云环境已提供）：

```sh
python3 -m unittest discover -s tests -p 'test_collector.py' -v
node --test tests/rules.test.js
python3 tests/test_demo.py
```

`tests/` 内的新闻仅是测试夹具，运行时通过 mock 提供，不会写入生产新闻 JSON。生产页面没有历史演示数据回退。网站无追踪脚本，录入与收藏仅保存在浏览器；源新闻 JSON 是公开内容。
