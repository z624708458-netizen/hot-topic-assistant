# 热点雷达 V4 · 每日选题与创作者第二大脑

在已有 V3 的 GitHub Pages 页面与 UI 上增加第二大脑，保留新闻、评分与现有UI，免费公开 RSS + GitHub Actions 定时采集 + 静态 JSON。不需要新增账号、服务器或付费 API Key，不调用 AI。

网站：https://z624708458-netizen.github.io/hot-topic-assistant/

## 最简单的免费架构

```text
公开 RSS → GitHub Actions（计划每两小时）
         → data/news.json（真实新闻，保留七天）
         → data/top5.json（近48小时的每日推荐快照）
         → GitHub Pages（原来的 main / 根目录部署）
         → 浏览器用同一套透明规则评分、筛选和生成框架
```

静态浏览器无法可靠跨域读取各媒体 RSS；浏览器端不使用公共 CORS 代理、不绕过网站限制。GitHub Actions 在服务器端读取公开订阅，网页只读取自己站点的 JSON。当前仓库是公开仓库，GitHub 的标准公开仓库 Actions runner 与 Pages 无需付费。工作流只使用 GitHub 自动提供的 `GITHUB_TOKEN`，不要求你购买或提供 API Key。

## 日常使用

- 默认近 48 小时，按分数、标题停留和公司/媒体限制挑出最多5条；≥60分且停留判断不低于中等才进入推荐。不足五条不会补编。
- 今天按北京时间自然日；48 小时与 7 天是滚动窗口。所有新闻明确显示原始发布时间到分钟（北京时间），不拿抓取时间代替。
- 公司筛选：小米、华为、腾讯、字节跳动、阿里巴巴、百度、OpenAI、苹果、特斯拉。多公司新闻可以被每个匹配公司的筛选找到。知名人物只有关联公司、没有公司名称时标记“人物热点”，关联公司仅用于筛选和避免重复，不代表公司涉事。
- 可以筛选 ≥80 分、搜索、查看全部新闻、按发布时间排列。Top 5 模式始终先挑合格候选并应用数量限制，再应用显示排序；“全部新闻”可以阅读低分和已降权候选。
- 每条有五维分数与关键词依据、推荐理由、普通人视角、3 个标题方向、60–90 秒分段口播框架、原文链接和来源摘要。
- 一键打开原文；标题与框架可复制。收藏保存本机快照，旧收藏不变成新热点。
- 手动新闻仍可录入，但默认不混入公开 RSS 推荐；勾选“包含手动录入”后才显示，始终标记未核验。

## V4 第二大脑：直接使用

1. 左侧点 **第二大脑 → ＋ 添加素材**，选择个人经历、个人观点、爆款结构案例、用户需求/评论或历史作品。
2. 可以只粘贴一段文字；标题留空时用第一行。所有补充字段都可选，之后点“编辑素材”再完善。不会自动填写你没有提供的经历、观点、作品或成绩。
3. 搜索会检查标题、全文、所有已填字段和标签；支持类型、标签筛选及时间升/降序。经历以所填日期、作品以所填发布时间排序，缺失时以首次保存时间排序。作品发布时间按北京时间输入。
4. 新闻“选题分析”下方会出现 **适合我讲吗？／我的第二大脑／我的切入角度**，能打开关联素材，展示最多5条历史素材、最多3个切口。
5. **我的收藏 → 转为历史作品**，填写自己的文案、平台、发布时间、播放/赞/评论/收藏及复盘。原收藏保留，新闻摘要不冒充作品文案；未知成绩为空，真实0保留。历史作品可反复编辑，知识库按已填播放量显示前3条，并在相关新闻分析中展示已记录表现。
6. “我的长期关注”可修改公司和领域；不自动推断你的身份、职业或立场。

### 数据在哪里

知识库和关注设置只保存在**当前设备、当前浏览器、当前网站域名的localStorage**，独立键为 `radar-brain-v4`，内部schema_version为1。刷新和正常关闭后重开仍在；不自动同步手机/电脑、不上传GitHub或第三方。V3收藏、手动录入、快照和RSS缓存的存储键没有变，没有自动清空或重置操作。

可以**导出JSON备份 → 在另一浏览器导入**。导入追加素材并合并长期关注；相同编号且相同内容跳过，相同编号但不同内容另外保存一条，不覆盖原素材。不合规备份整份拒绝，保存失败保留输入与已有数据。浏览器存储不可用/已损坏时提示问题并保留原始内容，不能声称保存成功。

清除网站数据、使用无痕模式或换设备时，浏览器不会保证数据留存；重要素材请定期导出，备份文件包含个人内容。导入上限10MB、最多3000条；浏览器自身容量可能更小，空间不足会提示并保留当前草稿。这版没有云同步服务或额外账号。

### 透明匹配与个人分

独立规则在 `assets/brain-rules.js`，界面与持久化在 `assets/brain.js`。完全不修改 `assets/rules.js` 中的V3新闻评分或Top5逻辑。

匹配使用已保存原标题、RSS摘要、可用的正文/关键词字段、公司与人物，对照素材标题、正文、补充文本字段和标签：

- 明确公司/产品别名匹配每个30，最多40；人物名称每个25，最多30；原标题/摘要直接命中素材标签每个15，最多30；共同主题（AI、房地产、职场、消费、汽车、手机、权益、商业等公开词表）每类10，最多30；合计上限100，是**素材相关性排序分**。
- 日期、数值表现和单独来源URL不会制造相关性。没有任何明确名称、标签或配置主题命中，就不匹配；不是向量检索或语义理解。页面逐项显示“为什么相关”和类型对应的使用建议。共同主题仍可能比较宽泛，请打开素材判断是否适用。
- 当前新闻仅有RSS摘要，**不会宣称已读原文全文**。不自动获取原文，也不替个人素材补写事实。

**个人匹配度**与新闻分、素材排序分是三件不同的事：有相关作品+20、观点+20、经历+20、结构案例+15、评论需求+15，长期关注命中公司/领域+10。每类只加一次，最高100，使用全部明确匹配的素材检查类别（下方只展示最相关5条），可点击加分素材核对。空库只有真实命中的长期关注分；没有素材不产生个人切口。

切口按三组组合：观点/经历的判断检验；用户问题/旧作品的新变化；爆款案例的结构借鉴（可同时引用其他相关素材）。每条显示一句话、匹配依据、实际素材编号链接与结构。优先用你填的案例结构，未填写时标明通用框架。不会复制案例原文、编造个人立场、推断未填写的作品数据或保证播放量。

## 来源与真实性

来源配置：`config/sources.json`。

当前启用 IT之家、爱范儿、极客公园、Apple Newsroom、OpenAI 官方新闻的公开 RSS。V3 在用户授权后验证了虎嗅、新浪科技/财经、小米投资者新闻和华为官方新闻：虎嗅读取超时，新浪/小米订阅长期未更新，华为日期没有时区，均暂不启用；36氪返回HTML继续停用。配置与页面保存停用原因，不将错误页面或旧新闻当每日热点。仅使用这些机器订阅地址，不抓取新闻正文、不绕过 403、登录、验证码或访问禁止。

每条保存标题、带时区的原始发布时间、公司及多公司匹配、媒体、原文 URL、简短摘要、来源 ID、采集时间。摘要直接来自 RSS，最多节选 360 字并标注；缺失摘要不编写。没有明确发布时间/时区、未来新闻、无效或来源域外的链接会跳过。促销领券信息和多事件早报排除，避免词语拼接抬高分数。标题中的“消息称”“曝光”“有望”等标记为待核验，不改写成官方确认。

公司识别是标题关键词和产品别名匹配，官方源有固定公司标签；不是语义理解。知名人物按公开姓名别名识别（雷军、任正非、余承东、马化腾、张一鸣、马云、李彦宏、马斯克、库克、Sam Altman等），不把单独“奥特曼”误认成人物。标题提到某品牌不意味着该品牌涉事、被处罚或作出回应。源提供的新闻和摘要也不能代替独立核验。传闻、官方计划及媒体分析需保留原文条件。发布短视频前必须打开原文核对。英文原题保留英文，未自动翻译。

覆盖范围有限：首次运行只能读取 RSS 当前提供的条目，七天记录从启用后逐步积累，不保证当天每家公司都有新闻，也不保证全网热点覆盖。不为了补足某家公司或五条推荐制造内容。

## 五维规则评分（100分）

规则版本3.0.0在 `assets/rules.js`；浏览器和自动推荐快照共用；不调用AI、不读取热搜/播放量。五维**最终分数**相加为总分（包含透明降权）。

| 维度 | 上限 | 规则 |
| --- | --- | --- |
| 大众认知度 | 25 | 华为/小米/苹果25，腾讯/字节/阿里/特斯拉24，百度22，OpenAI18；标题ChatGPT22；人物20–25；取最高值，不叠加 |
| 冲突/争议/反差 | 25 | 裁员收入、价格剧变、问责冲突、销量纪录、重大消费新品五组；标题一组17、两组22、三组以上25；仅摘要命中6–12，无命中2 |
| 普通人利益相关 | 20 | 钱袋子、常用消费场景、就业教育、用户权益；标题一组12，每多一组+4；仅摘要6/9/12/15；无命中4 |
| 社交传播潜力 | 20 | 标题基础4，大众对象+3，明确事件+8，生活关联+3，有意义数字+3，反差+2，知名人物表态+3；上限20；英文技术密集-4 |
| 时效性 | 10 | ≤12h10，≤24h9，≤48h7，≤7天3，更早/未来0 |

**低价值降权**仅依据原标题：普通系统/软件版本更新扣20、上限42；API/开发工具扣22、上限43；旧产品停止支持扣24、上限40；普通规格/渲染图泄露扣22、上限42；单功能/小交互扣20、上限43；专业研究/性能评测扣18、上限46。多条命中取最大扣分及最严格上限，不重复叠加；扣分从传播、冲突、利益三项依次扣除，认知和时间保持原值，页面显示原始分与最终分。标题明确出现裁员/事故/召回/处罚/诉讼等重大现实影响，或已确认的重大消费新品与生活关联时豁免，并提示核对原文；API价格改变不能借“新品”豁免。

**标题停留判断**只用标题：传播≥15、冲突≥14、利益≥10且无低价值降权为“较强”；大众对象+生活利益（或知名人物明确事件）且传播≥10为“中等”；其余或被降权为“较弱”。摘要中的工资/事故等词不能替标题制造停留理由。这不是实际停留率、播放量或爆款概率。

**Top 5**仅取≥60分且停留判断不低于中等的候选。同公司最多2条（联合公司及人物关联也计入）；同一媒体优先最多2条，来源不足时只有能增加合格推荐数量才放宽到3条，绝不超过3条。媒体按`publisher_id`归并（新浪科技/财经为同一媒体）。公司筛选时Top5仍遵守限制，需要更多可点击“全部新闻”。

关键词不理解否定和语境，例如“没有涨价”仍可能命中“涨价”。权重是公开编辑规则，不能证明争议或生活影响；英文原题不自动翻译。高分过滤和推荐可能为空，不强行调整分数凑数。

本次同一份真实数据、同一时钟的新旧规则对比见 [reports/V3-COMPARISON.md](reports/V3-COMPARISON.md)，完整分数在同目录JSON。冻结V2规则保存在 `scripts/legacy_rules_v2.js`，用于重现实验。报告是固定采集时刻的记录，网页持续更新。

推荐理由与角度是固定规则，标题是基于原题的模板；口播是按秒分段的**待填框架**，不生成未经验证的事实成稿。事实段需要阅读原文后填写，完成后朗读调整到 60–90 秒。

## 自动更新与现有 Pages

工作流：`.github/workflows/news-update.yml`。

- 默认分支 main 推送代码时、手动运行时、UTC 每两小时的第17分钟启动（北京时间偶数小时17分）。GitHub 调度可能延迟，没有精确到时的保证。
- 先跑采集与评分测试，再采集并生成 Top 5，将两个 JSON 提交回 main，不推送其他文件。
- 保留七天的有效缓存；单源失败不清空其他新闻，全部失败时保留尚未过期数据、保存失败状态并把工作流标为失败。页面显示每个源的状态与最后成功时间；超过六小时未成功采集时提示延迟。
- 浏览器每五分钟刷新同站 JSON，不在浏览器触发外部采集。网页“刷新数据”只读取已发布快照。
- `GITHUB_TOKEN` 的机器人提交不会自动触发普通 Pages 构建，所以工作流会**显式请求 Pages rebuild**，沿用现有 main / 根目录设置。若 Pages 本来就是 Actions 模式，则使用官方 artifact/deploy 动作。不擅自更改仓库设置或部署来源。
- 如果仓库禁用了 Actions、禁止写权限、Pages 环境要求审核，或者部署来源不是 main / 根目录，工作流会给出错误；需要仓库所有者在 Settings 调整相应现有配置。无需新增第三方账号。
- GitHub 可能按自身策略暂停长期不活跃仓库的定时任务，可在 Actions 中手动重新运行。

查看更新结果：GitHub 仓库 → **Actions** → **Update tech news and Pages**。需要手动刷新新闻时选 **Run workflow**；正常使用无需懂代码。

## 本地开发与测试

Python 3.12+、Node 22+（只用标准库，不需 npm install）。启动：

```sh
python3 -m http.server 8000 --bind 0.0.0.0
```

在本机浏览器访问 `http://localhost:8000`。云机器需要平台的端口转发。本版通过 HTTP 读取 JSON，不建议双击本地 HTML；直接访问已部署网站即可。

采集真实数据并生成快照：

```sh
python3 scripts/collect_news.py
node scripts/rank_news.js
# 可选：用相同采集时刻生成今日V2/V3对比快照
node scripts/compare_scores.js
```

验证（浏览器测试额外需 Python Playwright 与 Chromium；当前云环境已提供）：

```sh
python3 -m unittest discover -s tests -p 'test_collector.py' -v
node --test tests/rules.test.js tests/brain.test.js
python3 tests/test_demo.py
python3 -m unittest discover -s tests -p 'test_brain.py' -v
```

`tests/` 内的新闻仅是测试夹具，运行时通过 mock 提供，不会写入生产新闻 JSON。生产页面没有历史演示数据回退。网站无追踪脚本，录入与收藏仅保存在浏览器；源新闻 JSON 是公开内容。
