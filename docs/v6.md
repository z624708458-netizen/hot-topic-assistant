# V6.0 爆款内容情报系统：使用、配置与验收

## 先说明可用范围

本次从仓库实际的V5.2增量升级。旧新闻评分是透明规则，不是AI评分；旧知识库/收藏/口播草稿在浏览器localStorage，没有已有云数据库。仓库只发现OpenAI Provider，没有DeepSeek实现；无法读取用户线上Worker的Secrets，不能据此判断线上是否另外配置过DeepSeek。

V6新增独立作品库、SocialDataX适配、绝对/相对表现评分、内容研究、语义聚合、每日最多10条报告、原创口播和创作流程。**当前没有真实SocialDataX、DeepSeek或OpenAI凭据，也没有用户D1/Worker登录授权。真实第三方采集和模型生成尚未验收，不会以测试数据充实榜单。** 保存设置不代表自动部署或真实授权成功。

- V5.1：`radar-speech-v5`及旧草稿契约不改变，原OpenAI `/health`、`/generate`保持兼容。V6独立支持DeepSeek，不擅自改写旧Provider配置。

## 最简单的本地启动（无额外依赖）

需要Node.js 24（使用内置SQLite；CI使用Node22也支持）。在自己电脑的项目根目录运行：

```sh
node server/dev.mjs
```

浏览器打开 `http://127.0.0.1:8876/`。默认首页为V6；旧新闻入口为 `http://127.0.0.1:8876/#recommend`。

数据源设置中填写服务地址 `http://127.0.0.1:8876`，**仅本地开发**的默认应用访问码是 `LOCAL_ONLY_6_DEVELOPMENT_123456`。它不是任何API Key，不可用于线上Worker。服务仅绑定回环地址并校验Host，不能把它当公开生产服务器。可以用环境变量 `APP_ACCESS_TOKEN`覆盖本地访问码；程序不打印环境凭据。

本地库自动创建于 `.local/intel.sqlite`（已gitignore），刷新和重启保留；迁移是幂等CREATE，不删除旧库。没有Key也可连接作品库、维护博主、关键词、备份和创作流程；无外部数据时页面保持空白状态。数据库文件包含个人内容，不提交公开GitHub。线上使用D1，不把本地SQLite上传公开仓库。

## Cloudflare部署与数据库迁移

当前开发环境没有Cloudflare账号授权，**未替用户创建D1或更新线上Worker**。最简单的控制台路径：

1. 在已有Cloudflare账号创建D1数据库（如 `hot-topic-intel`）。不要删除已有数据库。
2. 在D1控制台执行 `server/migrations/0001_intel.sql`；若控制台只接受单条语句，逐条执行CREATE语句。全部表/索引均以 `intel_` 开头，`CREATE IF NOT EXISTS`可重复执行；没有DROP、ALTER或对旧数据的写入。
3. Worker → Settings / Bindings，添加D1绑定，变量名必须是 **INTEL_DB**，选择真实数据库。
4. 运行构建并用 `server/worker.bundle.mjs` **完整内容**替换Worker编辑器中的代码，Deploy。保留已有Secret，不删除旧OpenAI配置。
5. Worker Secret中沿用/设置至少24字符 **APP_ACCESS_TOKEN**。网页只填Worker根地址和这个应用访问码；不填API Key。
6. 网页“数据源设置”检查连接。`/intel/status`只显示配置状态，不验证Key是否有效、不产生模型/作品调用。

如已使用Wrangler，可在 `server/wrangler.toml`中按注释绑定自己的真实D1 ID，然后使用Cloudflare官方CLI迁移命令；不要填虚构ID，也不要运行重置数据库命令。控制台部署bundle不会自动读取toml中的变量和Cron，需要在控制台分别配置。

### 服务端Secret与开关

| 名称 | 设置位置/用途 |
| --- | --- |
| SOCIALDATAX_API_KEY | Worker **Secret**；不放网页、localStorage、仓库或聊天 |
| SOCIALDATAX_ENABLED | 文本 `true`，启用适配；默认关闭 |
| SOCIALDATAX_TERMS_CONFIRMED | 核对账号权限、数据取得方式、展示/缓存/保留规则后才设 `true` |
| SOCIALDATAX_BILLING_APPROVED | 用户确认该服务费用/积分使用后才设 `true`；没有Key不发起真实请求 |
| INTEL_MODEL_PROVIDER | V6选择 `deepseek` 或 `openai`；toml显式默认DeepSeek；不改变V5的Provider |
| DEEPSEEK_API_KEY / DEEPSEEK_MODEL | DeepSeek Secret与模型名；默认模型 `deepseek-chat` |
| OPENAI_API_KEY / OPENAI_MODEL | 如选OpenAI，沿用原服务端配置 |
| INTEL_MODEL_ENABLED | V6模型开关，默认false；显式false优先于旧MODEL_ENABLED。未设置时兼容继承旧开关 |
| APP_ACCESS_TOKEN | 私有应用访问码，不同于任何供应商Key；浏览器仅内存保存 |
| ALLOWED_ORIGIN | 继续使用 `https://z624708458-netizen.github.io`，不含仓库路径 |

所有业务端点精确Origin＋访问码认证，固定供应商域名，无任意上游代理。若以后在此云环境验证真实API，还需放行 `mcp.socialdatax.com`，以及实际选择的 `api.deepseek.com`或`api.openai.com`；当前没有请求这些业务端点。

### 定时采集（默认未启用）

完成授权、设置数据库及预算后，在Worker控制台添加Cron（例：每6小时）；再设置 `INTEL_AUTOMATION_ENABLED=true`。服务端按设置中的采集间隔检查关注且未暂停的博主；关键词检查也受间隔控制。首次只取一页，后续页可手动用原游标继续，**不承诺已完整监控账号全部新作品**。海量更新可能需要多页才能覆盖。

如另外确认转写、评论及模型的费用，才开启 `INTEL_AUTO_RESEARCH=true`：每次选最多3条高优先级作品，按预算取得详情/评论/转写并在文本可用时分析，然后生成当天报告。异步任务不阻塞等结果，下次只查已保存job_id。未开此开关时仅采集基础数据和生成已有证据报告。

Cron代码已实现，**本次没有在账号中创建Cron**。本地dev服务不运行后台定时器；有代码、有频率设置不等于线上自动运行。报告最多10条，没有足够模型研究或真实数据就空缺。

## 数据、预算与稳定性

- 作品唯一键是平台＋真实作品ID。源返回的原链接保留（小红书签名query不删、不用ID拼链接）；不构造缺失主页。
- 分平台Adapter映射可独立失败，不删除其他平台已有记录。工具必须存在且输入schema匹配才发起收费的tools/call。
- 按平台/操作/值/完整游标缓存，默认6小时。缓存复用不重复工具调用，也不将源获取时间改成现在。
- 支持分页和增量：保存next_page_token，不使用页码猜游标；超过每页或每日作品数量时保留已有数据、阻止推进，调整上限后可复用缓存继续。空游标不被当成完整覆盖。
- 每个Provider每日调用上限和全局每日作品处理上限，D1原子预留避免并发超预算；来源工具调用尝试包含失败或超时。MCP握手/能力发现不算作品工具调用；显示的成功模型请求仅指HTTP成功，不保证输出通过校验。
- 不自动重试可能收费的搜索/转写提交。网络异常保留原数据和游标，用户解决后手动重试；超时可能已被供应商计费。转写提交前记录意图：状态未知时停止再次提交，需在供应商核对；失败任务也不自动反复收费轮询。
- 成功任务用job_id继续，评论按真实游标分页、稳定ID去重；没拿到评论正文不推断评论区需求。标题/节选不是完整字幕；超过文本上限报错，不静默截断冒充全文。时间单位未验证时，不断言“前3秒”。
- 保存源原始作品响应及有限历史指标快照，用于重新评分；私有库不发布到GitHub Pages。已知凭据字段和凭据值脱敏，日志只有平台/操作/时间/状态，不记录原文、Key或供应商错误正文。
- 原始作品默认24小时保留，设置必须符合账号获准规则；读请求/定时任务清理到期记录，API即时排除过期作品。缓存时长不得超过保留时长。未关注的过期平台作者引用清理；过期粉丝快照置为未知，用户关注/手动笔记保留。
- 原始平台数据不能因备份导入延长到期时间。导入为“手动提供/未独立核验”，保留原来源信息，不冒充新的供应商认证证据，也不作为自动推荐来源。个人原创稿件与流程独立保留。
- JSON导入先完整校验、再原子batch合并；相同ID不覆盖已有记录，已有设置不被备份悄悄重置。单批备份上限850KB，超限分批处理，不静默截断。导出包含个人内容，用户自行保管并遵守数据源保留规则。
- 调用次数有本地记录；**没有供应商账单接口，因此实扣金额/积分为未知，不显示0元或把估算冒充账单**。以供应商账户实际账单为准。

## V6评分、聚合与推荐

绝对播放等级：S≥100万、A≥50万、B≥10万、C≥1万、D<1万；未知播放无等级，真实0为D。

基准只使用**同平台、同稳定作者ID、当前作品之前90天、最多30条作者作品列表样本**；不使用关键词搜索挑出的作品建基准，不把当前作品混进去。至少5条可计算，5–19条标小样本，建议至少20条；中位数为0或缺当前播放则不算倍数。导入未核验记录不混入供应商样本。倍数≥10超级异常、≥5强爆款、≥2明显超常、≥1正常；不等于内容质量，也未按曝光年龄归一化。

六项默认权重25/25/20/10/10/10，可独立编辑合计100，不修改V3和V4.1：

- 领域25：命中1～3个配置词，按命中数/3封顶；透明关键词规则。
- 绝对表现25：S/A/B/C/D分别乘1/0.85/0.65/0.35/0.1。
- 相对历史20：≥10/≥5/≥2/≥1/<1分别乘1/0.85/0.65/0.25/0。
- 互动10：已知赞/评/藏/分享合计÷已知播放，以5%封顶；缺项仅是下界，异常合计不评分，不宣称统计意义上的互动质量。
- 时效10：24小时内1、72小时内0.7、7天内0.4、更早0；缺日期/未来日期不评分。
- 创作价值10：必须来自模型分析0–10；未连接不由规则补写。模型判断内容方向、普通人关心、信息增量、观点、事实案例、短口播适配和争议空间。

缺维度显示“无法评估”，分母减少，不归一化成虚假100；按已知分排序。自动推荐要求供应商来源、真实发布日期近7天、领域命中、模型研究、已知分≥60且可评估上限≥70。最多10条，相关主题去重；模型确认的多作者主题保留合格来源作品，不把它们拆成重复新闻。规则主题线索和AI语义聚类分别标注；只有多个稳定作者支持才显示跨博主线索。**没有连续日期的完整采样，不声称增长/衰退，不画虚假热度曲线**。

## 内容研究、原创与个人闭环

每条作品可取得详情、ASR任务、真实评论，再让模型拆解。原文证据须确实出现在输入；没有评论时明确无法分析评论需求。模型仍可能误解真实文本，证据片段存在不证明其推理正确，需打开原作品核对。

原创稿目标400–500字，允许按事实量调整，附3开头、3标题、核心观点、来源和待核实事实。不复制参考长段，不拿传播指标当裁员人数等事件事实。只读选中的第二大脑高相关样稿/观点，不上传整个知识库；相关已发布V6作品的真实成绩/复盘也可供模型参考，不自动改变旧权重或预测新稿播放量。

“我的选题库”支持待创作/创作中/已完成/已发布/暂不考虑；用户手填真实播放、赞、评论、收藏，空白留空。当前是**规则＋模型参考的反馈闭环，不是已训练的自动学习模型**。既有V5草稿与V4作品不会被新稿覆盖。
